# Execute an authorized slice

**Enter when:** implementation is requested for a reviewed slice with actionable tracker handoffs. For a focused direct code change without a ticketed slice, follow design's fidelity procedure and project implementation rules; do not invent tickets solely to enter this playbook.

**Read:** slice parent, selected task and prerequisites, exact accepted target/review, affected design-map entries and project checks; [delegation](../references/delegation.md), [preserve settled decisions](../principles/preserve-settled-decisions.md), and [proportionate evidence](../principles/proportionate-evidence.md). Resolve actual project execution policy through [project bindings](../references/project-bindings.md).

## Deliver the slice

1. Select actionable work within the authorized slice and agree who owns the tracker claim. Dispatch a fresh independent worker per ticket with exact task/shared-context links, writable ownership, applicable principle paths and the [worker brief](../assets/worker-brief-template.md). Tell workers they are not alone and must preserve others' edits. The coordinator may persist.
2. Follow project scheduling policy. Without a recorded policy, use one worker at a time. When the project requires sequential independent workers per ticket, verify returned behavior, evidence and status before the next dispatch and do not reuse a worker across tickets. If delegation is unavailable, report the limitation and continue independent permitted work rather than silently claiming the required execution policy was satisfied.
3. Verify the returned artifact, relevant behavior and focused checks. Resolve actual blockers; continue only independent authorized work. Keep simulations distinct from real mechanism evidence. Respect hooks and commit policy without stashing, rewriting or staging unrelated work.
4. During implementation, maintain required module/review coverage, supported imports, important states, accepted-target updates and qualifying design decisions. Use [design](design.md) for matched fidelity checks. Record a newly established decision with its actual status; preserve settled direction and return material scope changes to [planning](planning.md).
5. Run required integration/completion gates and demonstrate the operable slice against its accepted target. Verify design-record placement, inventory links, review-only production exclusions and applicable checks. Repeat checks only for changes, failures or unresolved risks; bound automation and retries.
6. Present the integrated result for required human review. Implementation completion does not establish acceptance. Refine feedback within scope; close the slice only when required work, record updates and actual user acceptance are satisfied.

**Deliver:** verified outcome and task/artifact links, real/simulated boundaries, exact checks and limits, and the pending acceptance or next actionable work. Do not infer acceptance from worker completion or passing tests.
