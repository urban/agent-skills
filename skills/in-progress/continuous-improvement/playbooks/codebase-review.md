# Review the codebase

Examine what the project produces: source, contracts, tests, configuration, examples, and supporting repository artifacts. The entrypoint owns principle reading, scope, standards, prioritization, and the shared report.

1. **Map broadly, inspect selectively.** Locate product capabilities, ownership, supported entrypoints, dependencies, checks, and representative behavior. A whole-codebase request needs a broad map before choosing deeper investigations; state what remains uninspected. Use reported pain, likely upcoming work, and change history as leads, not proof of poor design.
2. **Trace a representative change.** Follow actual callers, domain decisions, authoritative state, external dependencies, and verification. Record where readers reconstruct unrelated internals, repeat obligations, edit scattered policy, or pay for unrelated checks. Ask what the capability does, guarantees, and owns.
3. **Find simpler alternatives.** Consider names, deletion, consolidation, valid-state modeling, deeper modules, clearer ownership, and narrower supported contracts. Identify hidden ordering, recovery, cancellation, or resource obligations. A useful boundary reduces caller knowledge; adding an interface or package alone does not establish that benefit.
4. **Weed out misleading paths.** Inspect implementations and the examples, exports, fixtures, and instructions agents imitate. For each obsolete or bad path, identify the supported alternative and all affected consumers. Distinguish intentionally invalid tests, necessary compatibility, and useful rationale from misleading production examples. Propose migration and removal together; do not preserve a known bad path merely to reduce the diff.
5. **Check the recommendation.** Show concrete locations and a small before/after sketch for shortlisted changes. Explain the future change made easier, which complexity disappears, migration obligations, and behavior that must remain. Static evidence is sufficient for a demonstrated structural issue; use the cheapest focused check for uncertain behavioral claims. Keep source absence, failed behavior, and missing access distinct.

Return candidates to the shared report. Include code worth retaining. Do not invent opportunities to fill categories, redesign every boundary, or construct a complete migration for every candidate. Suggest enforceable prevention where it removes repeated mistakes, using existing tools first.
