# Review through hypotheticals

Use concrete proposals to discover judgment the draft does not yet capture.
Useful fault lines include a valuable off-mission feature, competing commitments, a reasonable first step that expands future obligations, or a change in audience.

For each proposal, show:

- The specific change and its consequences.
- The passage of the draft it tests.
- The strongest reason to accept and the strongest reason to resist.

Invite an accept, resist, or conditional verdict with reasoning; allow a different framing when the proposal contains a false premise.
Probe an unexplained verdict only when its reason would materially change the vision.
Do not turn disagreement into an attempt to persuade the owner toward the draft.

After a batch, show the revised text and briefly map each answer to the resulting change.
Merge overlapping reasoning instead of adding a section for every answer.
Where the answer exposes an implementation accident, express the desired outcome rather than canonizing the current mechanism.

Before final review, apply the revised vision to a fresh proposal.
Explain the likely judgment using the document alone; ask the owner if the result remains uncertain.
Stop adding hypotheticals when they no longer reveal consequential gaps.
This is a review technique, not a permanent test suite or additional project artifact.

Method adapted from [Kun Chen's vision skill](https://github.com/kunchenguid/vision) and its [demonstration](https://www.youtube.com/watch?v=X3bhjQbxnMg).
This version uses a concise entrypoint, bundled review guidance, and the owner's available review surface rather than requiring a particular board tool.
