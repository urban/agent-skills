# Prefer an operable outcome

**Apply when:** choosing the UI outcome and comparison boundary for an iteration or fidelity review.

Choose a UI result the user can operate and evaluate within a short comparison and feedback loop; return implementation implications to the caller. Include the whole loop's cost. Separate real capability from simulation, and probe uncertainty that could invalidate the selected outcome early.

**Example:** compare import placement and recovery in the existing reader using controlled transcript fixtures before exploring unrelated attribution controls. Keep the simulated import dependency explicit.

**Tradeoff:** the smallest code change may not deliver useful user value. Keep necessary integration and consequential recovery in scope; defer adjacent ambition. A required human decision ends the dependent iteration until resolved.
