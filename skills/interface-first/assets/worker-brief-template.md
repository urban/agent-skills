# Worker brief

Fill only the context needed for this bounded assignment. Send actual file paths and source links; do not send the whole library.

- **Goal and task:** operable outcome or precise source question; exact ticket and shared slice links where applicable.
- **Ownership:** writable files/capability or read-only role, exclusions, tracker claim owner, commit policy and isolated output location if needed. You are not alone in the codebase: preserve others' edits and accommodate concurrent changes.
- **Read:** project instructions, affected design-map entries, accepted target/review and selected playbook/principle paths. Follow only necessary deeper links.
- **Behavior boundary:** approved units/states, caller-visible inputs/outputs and failures, observable effects, production capability, real internal composition, supplied external dependencies, and settled decisions.
- **Acceptance bar:** observable completion predicate; exact focused checks and the distinct claim each establishes; mandatory project gates. Include relevant revision/configuration/input context for returned evidence. Do not infer human acceptance from implementation success.
- **Live evidence, only when needed:** named feasibility/compatibility/quality question, selected cases, criteria, run/time limit, and what fixtures leave unproven.
- **Stop and escalation:** stop when the stated bar passes; inherit it across handoffs without adding gates or duplicating valid verification. Revise it explicitly for a consequential new defect, unmet requirement, changed composition, or scope decision. Report exhausted evaluation limits and acceptance gaps.
- **Return:** `PASS`, `ISSUES` or `BLOCKED`; artifact paths and concise findings, checks/evidence, simulation limits and remaining decisions. Do not dispatch more workers unless explicitly assigned that responsibility.
