# Project design reference

Use this template only when the project has no equivalent map. Replace guidance with observed facts and real links before delivery. Preserve an existing inventory format and any checker markers.

## Start here

Explain how to read the overview and affected records progressively. Link owning accepted designs, decisions, source and runnable review instructions.

## Owners and current targets

Identify the primary owners, accepted targets, implementation gaps and relevant ADRs. Distinguish proposal, running behavior and accepted direction.

## UI relationships and inventory

Describe the supported screens, flows and compositions. For each meaningful unit, provide its name, purpose, parent/children, responsibility, semantic interface, behavior/lifetime authority, reuse/placement, supported module entry, review source/scenarios, important states, reset path, consumers and owner/target links. Use concise records with deeper links; do not manufacture missing history or leave an assessment scaffold.

## Principles and composition grammar

Capture known project guidance and provenance. Separate explicit accepted constraints from interpretations or proposals. Preserve established rationale without requiring explanations for every existing property.

## Workflow integration

Link design/ADR/plan/evidence locations, UI-module conventions, review tooling/operating instructions, focused checks, task backend/hierarchy and execution/commit/review policy. Verify commands and reachable scenarios; label unavailable capabilities accurately.
